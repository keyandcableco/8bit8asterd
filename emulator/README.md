# 8b8 emulator

Runs **the actual firmware** in a browser against three emulated AY-3-8910s.
`host.cpp` includes `8b8_firmware.ino` as a single translation unit, exactly
as the Arduino IDE builds it, so there is no second implementation to drift
out of step with the hardware.

The firmware needed one four-line change for this: an `AY_EMULATOR` seam in
`writeReg()` that hands register writes to the emulated chips instead of
bit-banging pins. It compiles to nothing on AVR.

## What's here

    arduino_shim.h   pins, PROGMEM, timers, EEPROM, Serial -- host stand-ins
    MIDIUSB.h        stub; the page injects note events into its queue
    MIDI.h           stub; DIN MIDI has no meaning in a browser
    ay8910.h         the chip: 3 tone channels, LFSR noise, envelope, log DAC
    host.cpp         drives setup()/loop(), renders audio, exposes the API
    emulator.html    GENERATED by ../generate.py -- same panel as index.html
    build-native.sh  g++ build for the tests
    build-wasm.sh    emcc build for the browser

## Build and run

    ./build-wasm.sh          # once emsdk is on your PATH
    python3 -m http.server 9111
    # open http://localhost:9111/emulator.html

Press **Start Audio**, then play with the letter keys (top rows pitched,
bottom row drums) or a MIDI keyboard.

## Tests

    ./build-native.sh && /tmp/8b8emu /tmp/out.wav

Renders a chord and a drum pattern to a WAV. `temper_test.cpp` reads the tone
periods the firmware programs and checks the temperaments land where they
should.

## Fidelity

The chip model steps at clock/8. The datasheet's tone frequency is
clock/(16*period) and the output toggles once per period, so a full square
cycle is two periods. Noise shifts every `2*period` steps and the envelope
advances every `32*period`, matching clock/(16*NP) and clock/(256*EP). The
DAC is the chip's logarithmic one, about 3dB per step.

Output is high-passed at about 3.5Hz to model the coupling capacitor on a
real board, so a muted channel's DC level does not appear as offset.

Not modelled: analogue output stage, supply noise, chip-to-chip variation,
and the exact bus timing (register writes go through the seam rather than
being decoded off BDIR/BC2).
